# 영속성과 고가용성

- 영속성: 서버를 다시 켰을 때 남아있는 것 (RDB, AOF)
- 고가용성: 서버가 고장이 나도 서비스가 계속 운영이 되는 것

# 고가용성

- 한 대가 쓰러지면 다른 한 대가 대신하는 방법
- 서버 한 대로 모자랄 때, 여러 대로 나누는 방법

# 용어 정리

- 고가용성: 서버가 고장이 나도 서비스가 계속 운영이 되는 것
  - 고장, 정전, 운영체제가 강제로 레디스 서버를 죽임
  - 문제: 접속 자체가 되지 않는다.
  - 해결: Replication + Sentinel

- 확장(scale-out): 데이터나 요청이 늘어도 감당하는 것
  - 데이터가 한 대의 메모리에 다 안 들어갈 때
  - 문제: OOM(Out of Memory)
  - 해결: Cluster

- 서버가 고장나는 것을 대비하는 역할
  - master: 쓰기를 받는 원본
  - replica(slave): 마스터의 내용을 실시간으로 따라 받는 복제본, 읽기 전용
  - replication: 마스터 -> 레플리카로 데이터를 흘려 보내는 기능

- 서버가 고장났을 때 일어나는 문제
  - failover: 마스터가 죽었을 때 다른 서버가 물려받는 과정
  - promotion: 레플리카를 마스터로 올리는 것
  - sentinel: 마스터를 감지하다가 마스터가 죽으면 failover를 자동으로 해주는 프로그램 (Redis)

- 확장을 위한 역할
  - cluster: 여러 Redis를 한 덩어리로 묶어 데이터를 나눠 담는 구성
  - node: 클러스터를 이루는 레디스 한대
  - sharding : 데이터를 쪼개 담는 것
  - shard: 쪼개진 한 조각
  - hash slot: 키 이름으로 계산한 칸 번호, 칸마다 담당 노드가 정해져 있다.
