Redis 2대

- 마스터 (6379)
- 레플리카(6380): read only

센티넬(sentinel)

```bash
cd ~/redis-practice/repl
cat > sentinel.conf <<'EOF'
port 26379
sentinel monitor mymaster 127.0.0.1 6379 1
sentinel down-after-milliseconds mymaster 5000
sentinel failover-timeout mymaster 10000
EOF
redis-sentinel sentinel.conf
```

- port 26379: 센티넬도 레디스의 한 종류, 26379 포트 사용
- sentinel monitor mymaster 127.0.0.1 6379 1
  - 6379 포트를 mymaster라는 이름으로 감시한다
  - 마지막 1 = 마스터가 죽었다고 확정하려면 센티넬 몇 개가 동의해야 하는지 (쿼럼)
- down-after-milliseconds: 5초 동안 응답이 없으면 죽은걸로 판단 (기본값: 30초)
- failover-timeout: failover 작업이 꼬였을 때 다시 시도하기까지 기다리는 시간
  ⚠️ 센티넬 탭에 `+slave` 줄이 뜬 걸 확인하고 다음으로 넘어가기

sdown : 센티넬이 '마스터 죽은 것 같은데?' 하는 메시지
odown : 센티넬(여러 개일 수도 있음0)이 '마스터 죽었다!!'라고 확정한 메시지

정석
센티넬: 3대
쿼런: 2개

메모리가 모자랄 때 레플리카를 쓰면 해결이 될까? : X

- 메모리가 모자라면 같이 들고 있는 애를 구하는게 아니라 나눠서 들고 있는 애를 구해야 한다.
- 레플리카: 같이 들고 있는 애

오늘: 7001 7002 7003 각 노드가 다 마스터
실무: 마스터 노드 3대 + 각 레플리카 3대
클러스터를 사용하면 센티넬을 따로 두지 않는데, 왜냐하면 페일오버를 클러스터 스스로 할 수 있기 때문이다.

- 센티넬: 마스터가 죽었을 때 레플리카를 마스터로 승격시켜주는 역할(자동 페일오버), 지금 마스터가 누구인지 알려줌
- 클러스터: 해시 슬롯을 여러 노드가 나눠 가져서 메모리 부족을 해결하는 역할
- 레플리카를 늘리는 건 확장이 아니다 = 메모리가 부족할 때 레플리카를 늘리면 안된다.
