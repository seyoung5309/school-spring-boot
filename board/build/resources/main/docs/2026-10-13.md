# DTO
우리 코드의 문제점: 응답은 너무 많이 나가고, 요청은 너무 아무거나 들어온다. 
Data Transfer Object: 데이터를 옮기는 것만 하는 객체
- API가 주고 받는 모양, request, response의 모양을 엔티티와 별개로 따로 저장해주는 클래스
- request dto, response dto가 따로 있다. 
- request dto: 클라이언트가 보내도 되는 것
- response dto: 클라이언트에게 보여줄 것
- DTO를 사용함으로써 DB와 API를 분리할 수 있다. 
- DB <-Entity 클래스
- HTTP Request, API <-> DTO 클래스

---

1. Controller에서 Post 엔티티가 사라짐
- 컨트롤러는 엔티티를 몰라도 됨
- (String) 형변환도 사라짐
- 변환하는 로직은 Service에서 딱 한 번 PostResponse.from()
- 목록은 Service 클래스 내 toResponse() 메서드 활용

2. DTO 도입
- 한 줄도 바꾸지 않은 곳 -> PostRepository
- 저장 방식을 바꿀 때는 repository만 건들고, controller는 안 건듦
- API 모양을 바꿀 때는 controller, service만 바꾸고 repository는 안 건듦
