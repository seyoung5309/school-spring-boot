# 트랜잭션 @Transactional
작업의 단위
- 여러 개를 동시에 변경하는 작업
- 게시글을 수정한다. 단일 작업도 트랜잭션
- 전부 되거나, 전부 되지 말아야 한다. all or nothing
- 커밋, 롤백
  - 커밋: 지금까지 한 작업을 DB에 반영
  - 롤백: 지금까지 한 작업 되돌리기
  - 커밋한 이후에 롤백 불가

# AOP
aspect, 관점 지향 프로그래밍
공통 관심사를 따로 떼서 한 곳에 모으고 어디에 적용할지 고민한다. 
스프링은 AOP를 구성한 대표 프레임워크 

# AOP 용어 정리 
- Aspect
  - AOP의 주인공, 관점
  - 공통 관심사 하나를 의미함
  - 오늘 코드: ExecutionTimeAspect 클래스
  - 이전에 했던 것: LoginInterceptor 클래스 
  - @Transactional도 스프링이 만든 aspect
- Advice
  - 조언
  - 언제, 뭘 할지를 의미
  - 오늘 코드: @Around 어노테이션이 붙은 measure 메서드 
  - 이전에 했던 것: @RestControllerAdvice
  - 실무에서는 @Around 어노테이션 말고도 다양한 방법으로 advice를 만들 수 있음
    - 어떤 메서드가 실행되기 전에만 해줘! @Before
    - 실행하고 나서 해줘! @After
    - 예외가 날 때 해줘! @AfterThrowing
- Pointcut
  - 적용 지점. 어디에 적용할건가
  - 오늘 코드: execution(* com.mirim.board..*Service ~~)
  - 이전에 했던 것: addPathPatterns("/members/me") <- 로그인 검사 어디서 할지 
- JoinPoint 
  - 끼어든 지점. 핵심 관심사 
  - 원래 메서드 실행하고 와: joinPoint.proceed()
- Aspect = Advice + Pointcut의 조합 
  -공통 관심사? 따로 뗴서 모아놓고, 어디에 적용할지? 나중에 정한다. 

AOP의 핵심을 여러 곳에 반복되는 공통 관심사를 한 곳에 몰아넣고 적용할 곳을 지정하는 것.
