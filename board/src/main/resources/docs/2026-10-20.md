- 의존성 2개 추가
  - 스프링 시큐리티의 비밀번호 해시를 위한 크립토

# 입력값 검사
postman -> dispatcherServlet -> (JSON -> SignupRequest 변환)
-> @Valid 검사 -> Controller -> Service -> Repository -> H2

- 입력값 검사를 하면 요청이 컨트롤러에 가기 전에 request body를 검사한다. 
- postman에 뭐가 잘못되었는지 안보임, 콘솔에는 보임

## 순서
1. DTO에다가 어노테이션으로 규칙을 정한다.
2. 컨트롤러에다가 @Valid 어노테이션을 붙여서 스프링한테 객체 검사를 요청한다. 

# 예외 Exception
- throw 키워드로 예외를 던질 수 있다.
- try-catch로 예외를 잡을 수 있다.
- 예외가 터지면 그 메서드를 호출한 쪽으로 넘어간다. 
- 아무 곳에서도 예외를 잡지 않으면? 프로그램이 죽는다.

## 스프링에서는 어떻게 될까? 
postman -> dispatcherServlet -> Controller -> Service -> Repository -> H2
예외가 발생할 때 서버가 죽지 않는 건 dispatcherServlet이 마지막에 받기 때문이다.

# 로그인
- 비밀번호가 맞는지 확인하는 것
- 다음 요청에서도 로그인을 했다는 사실을 기억하는 것
- 서버 입장에서는 로그인한 요청과, 정보 보여줘라는 요청이 같은 사람인지 알 수 없다. 
  - HTTP 요청 하나하나가 독립적이고, 무상태(stateless)
  - 세션: 서버 메모리에 있는 사용자별 보관함 
  - 세션 id: 쿠키에 저장, 보관소가 주는 번호, 클라이언트가 요청마다 자동으로 들고 다님. 
- 세션에 무엇을 넣어야 할까?
  - 엔티티를 통쨰로 넣으면? 비밀버호가 있어서 보안에 취약하고 무겁다. 
  - 사용자 id(pk)
- 세션이 서버 메모리에만 있다. == 서버를 재시작하면 로그인이 풀린다.
